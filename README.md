# 稽核駐站分配系統

GAS Web App：完整稽核管理平台——駐站收案三年週期＋七類中心層級稽核項目的計劃、追蹤、統計與紀錄。

## 八類稽核類型

| # | 類型 | 頻率 | 對象 |
|---|---|---|---|
| 1 | 駐站收案作業 | 每駐站三年一次 | 逐駐站（「駐站收案稽核」分頁） |
| 2 | 招募宣導及公眾溝通 | 每三年（跟隨全域模式與起始年） | 中心層級 |
| 3 | 退出與再聯繫 | 2024 年起每四個月（1–4 月／5–8 月／9–12 月）；2023 年（含）以前每半年 | 中心層級 |
| 4 | 中心不可辨識個人之資料與檢體之處理作業及儲存 | 每年 | 中心層級 |
| 5 | 資安保護及其他資料庫管理事項 | 每年 | 中心層級 |
| 6 | 資料庫之運用 | 每年 | 中心層級 |
| 7 | 組織與人員 | 事件觸發（展延／變更／倫委會組成／人員異動） | 中心層級 |
| 8 | 不定期稽核 | 依指示執行 | 中心層級 |

**中心稽核項目**（「中心稽核項目」分頁）：每項可「排定稽核」（人員與預定日期**可獨立設定、至少填一項**，先排日期會立即建立行事曆預約、之後補人員修改同一筆）、「登錄完成／補登」（任意日期，完成後排程自動清除）；類型 7 以「登記觸發事由」產生待辦，稽核日期 ≥ 事件日期即自動銷案；統計列顯示今年應稽／已完成／已排定／逾期待辦。

**年代制頻率**：類型 3 的期別歸屬依「紀錄日期當時的制度」計算——2023 以前的紀錄以半年制歸期（上／下半年）、2024 起以四個月制歸期；補登時 modal 即時顯示所選日期的期別歸屬，同期已有紀錄會顯示軟性提醒（不阻擋）。

**Google Calendar 同步**：駐站分派與中心排定會在指定行事曆建立整日事件（標題【稽核】＋名稱、說明含人員與年度/事由），並邀請稽核人員為與會者（自動寄送邀請）。**事件採同一筆預約增修**：先訂日期時即建立事件（標題附「待指派人員」），之後補人員時以 `calendarEventId` 找回**同一事件**修改與會者與內容（受邀者收到的是更新而非取消＋新建）；僅指派人員、尚未定日期者只寫入試算表、待日期確定再進日曆。取消分派、清掉日期時同步刪除事件。行事曆同步失敗不影響 Sheet 寫入，訊息會附註原因。

**駐站稽核紀錄日期化**：登錄今年稽核自動帶當天日期；補登改選完整日期（同年已有紀錄即時擋存）；卡片「上次稽核」顯示年月日（早期僅年度的資料顯示「YYYY 年」）；**點擊駐站卡片**可開啟歷年稽核紀錄清單。

## 業務規則（類型 1：駐站收案）

- **週期模式**（前端右上角可切換，存於 Script Properties、全域生效）：
  - **固定三年區段**（預設）：以「起始年」為錨點切分（預設 2026 → 2026–2028 一輪）。起始年可在前端「⚙ 週期設定」變更（同樣存 Script Properties，全域生效）。
  - **滾動式三年**：每站以「上次稽核年＋3」為到期年（2026 稽核 → 2029 起再次候選）；從未稽核過＝立即候選。
- **ISO 認證駐站**：採**兩年一輪排程**（人力上每年只稽部分家數，兩年內每家稽一次；固定模式錨點同 `CYCLE_START_YEAR`，如 2026–2027、2028–2029；滾動模式效期兩年）。卡片狀態與「今年建議家數」依此兩年輪計算。
  - **認證身分帶生效年度**：身分真相來源為外部「認證駐站紀錄」表（見下方資料來源），以「指定時間～換掉時間」區間記錄每家認證任期；指定時間的年份＝**認證生效年度**（`certifiedSince`）。**兩年排程輪只納入認證生效年起的稽核紀錄**，升認證前（還是一般站時）的稽核不算進兩年輪。未設定該表時退回組織架構樹 I 欄 `V` 判定（生效年未知，不過濾，等同舊版）。
  - **覆蓋率併入三年總覽**：認證駐站與一般駐站算同一個三年週期覆蓋率，三年內稽過就算覆蓋（**用全部紀錄、不分當時身分**）、**每家只算一次**；到三年週期第三年，前面已稽過的認證站不重複計入、也不因「兩年新一輪尚未稽」被當成未覆蓋。（排程維度與覆蓋率維度分離，見 `AuditCycle.js` 的 `evaluateStationFor_`）
- **一般駐站**：固定模式＝三年週期內稽核過一次即完成本輪；滾動模式＝效期三年。
- **年度建議數**：固定模式 = `ceil(未稽核一般駐站 ÷ 三年剩餘年數)` ＋ `ceil(本兩年輪未稽認證駐站 ÷ 兩年剩餘年數)`；滾動模式 = 今年到期的一般駐站全部 ＋ 排程到期的認證駐站全部。
- **稽核人員**：HR「人員職務配置」中 C 欄 = `TF-ISPI-GRP-AUDIT` 且 E 欄 = `稽核員` 者。
- **稽核分派**：候選駐站可設定稽核人員與預計日期，**兩者可獨立、至少填一項，每次儲存即立即寫入**「稽核分派」工作表（不再有草稿批次送出）。卡片依完整度顯示三態：人員＋日期＝**待稽核**、僅日期＝**已排定·待指派人員**、僅人員＝**已指派·待定日期**；三態皆可再開同一彈窗補齊或「取消分派」。登錄稽核紀錄後轉為**今年已稽核**。
- **歷史補登與稽核履歷**：每張卡片可「補登紀錄」任意歷史年度（2000～今年，已登錄年度自動鎖定）；卡片顯示「上次稽核年（共 N 次）」，從未稽核或距上次稽核**滿三年**時顯示磚紅「⚠ 已超過三年未稽核」警示（與週期模式無關的事實陳述）。

## 檔案結構

| 檔案 | 職責 |
|---|---|
| `env.js` | 試算表 ID、週期設定、欄位索引（唯一需要修改的檔案） |
| `AuditCycle.js` | 駐站週期計算純函式（可用 node 測試） |
| `CenterAudit.js` | 中心八類稽核類型、頻率策略純函式（可用 node 測試） |
| `CsvUtil.js` | CSV 序列化／解析／合併去重純函式（匯出匯入用，可用 node 測試） |
| `DataService.js` | HR 試算表跨表讀取、稽核紀錄讀寫 |
| `code.js` | `doGet` 與前端 API |
| `deploy.js` | 稽核紀錄工作表初始化 |
| `index.html` | 前端（直接用瀏覽器開啟 = 假資料預覽模式） |

## 部署步驟

1. 開啟 [script.new](https://script.new) 建立新 Apps Script 專案，命名「稽核駐站分配」。
   - 建議改從一個新的 Google Sheet 進入「擴充功能 → Apps Script」建立**綁定專案**，稽核紀錄就存在該試算表，`AUDIT_SPREADSHEET_ID` 可留空。
2. 依檔名逐一建立檔案並貼上內容（`index.html` 建立為 HTML 檔；`appsscript.json` 需在專案設定勾選「顯示 appsscript.json 資訊清單檔案」後貼上）。
3. 修改 `env.js`：
   - `HR_SPREADSHEET_ID`：HR_managerv3 試算表網址 `/d/` 與 `/edit` 之間的字串。
   - 確認 `CYCLE_START_YEAR` 是否為實際週期起始年。
   - `ISO_STATION_SPREADSHEET_ID`（選用）：認證駐站紀錄試算表 ID；留空＝退回組織架構樹 I 欄 `V` 判定認證身分。
   - `CALENDAR_ID`：稽核排程同步的行事曆 ID（留空 = 部署者預設行事曆；指定行事曆需有編輯權限）。
4. 在編輯器選取 `deployAllSheets` 執行一次（首次會要求授權，含 Calendar 權限），建立五張工作表：
   「稽核紀錄」「稽核分派」「中心稽核紀錄」「中心稽核排程」「稽核觸發事件」。
   **既有環境升級（v5）**：改執行 `upgradeSheets()` 一次，補上三個新欄位表頭
   （稽核紀錄「稽核日期」、稽核分派與中心稽核排程「行事曆事件ID」）；既有資料列不受影響。
   升級後重新部署，首次操作會要求 Google Calendar 授權。
5. 部署 → 新增部署 → 網頁應用程式：
   - 執行身分：**我（部署者）**
   - 存取權限：依 `appsscript.json` 為網域內使用者。
6. 開啟部署網址，確認讀到真實駐站清單、認證駐站帶金色「ISO 認證」標記。

## 稽核紀錄匯出匯入

駐站與中心兩分頁的統計列下方各有「匯出 CSV／匯出 Excel／匯入 CSV」工具列。

- **匯出**：CSV（含 UTF-8 BOM，Excel 開啟不亂碼）或 Excel（`.xlsx`）。下載於瀏覽器端產生，不受 GAS sandbox 限制。
- **匯入**：僅收 CSV，採**合併模式**——以去重鍵比對現有資料（駐站＝代碼＋年度；中心＝類型＋日期），只新增不存在的紀錄，重複者一律跳過，**不刪除既有資料**。匯入後回報新增／跳過筆數。表頭以欄位名稱定位，順序不限；缺欄會中止並回報。
- **歷年紀錄管理**：點擊任一駐站或中心項目卡片即開啟「歷年稽核紀錄」彈窗，內含每筆紀錄的期別／計入週期標記與刪除按鈕，並可由此補登。卡片本身維持精簡，不再顯示年度／日期標籤。

> **Excel 匯出授權**：`.xlsx` 匯出會建立暫存試算表並透過匯出 URL 取得檔案，首次使用需授權 Google Drive 與 UrlFetch 權限。僅匯出 CSV 則不需要。

## 資料來源

- **駐站清單**：HR 試算表「組織架構樹」，代碼 `GRP-CO-` 開頭的節點；I 欄 `V` = ISO 認證（未設定認證紀錄表時的 fallback）；G/H 欄 = 負責人。
- **認證駐站紀錄**（選用）：外部獨立試算表「認證駐站紀錄」工作表（`ENV.ISO_STATION_SPREADSHEET_ID`），以區間記錄每家認證任期——B 欄駐站代碼、D 欄指定時間（＝認證生效年）、E 欄換掉時間（空＝仍在認證），其餘欄位（紀錄ID／名稱／指定人／換站操作人／批次ID）供軌跡追溯。本系統**只讀**；設定後即以此表為認證身分真相、覆寫 I 欄判定。
- **駐站成員**：HR 試算表「人員職務配置」，C 欄（所屬組別代碼）= 駐站代碼。
- **稽核紀錄**：本系統「稽核紀錄」工作表，只存原始事實（駐站 × 年度），「是否計入週期」由讀取時計算，刪改紀錄後狀態自動正確。
