# 駐站卡片跨專案調派資訊設計規格書

> 專案：`biobank_manager/稽核駐站分配`
> 唯讀資料來源：`biobank_manager/twCohort` 的資料試算表
> 來源契約：`/home/itsutaka/biobank_manager/twCohort/docs/spec-station-dispatch-cross-project-reading.md`（v1.0）及現有儲存格式
> 日期：2026-10-07
> 狀態：設計待使用者複核

## 1. 目的與邊界

稽核員在駐站卡片查看指定日期，或在「排定稽核」彈窗選擇預計稽核日期時，能看到該站**已登錄的護理師調派狀況**，據此安排稽核時程。本功能只在本專案新增唯讀介接及畫面；不修改 twCohort 程式碼或試算表。

調派紀錄不是刷卡、請假或實際到勤資料；HR「人員職務配置」也不是逐日出勤表。因此介面只聲稱「有／無已登錄調派」，不聲稱某人當日確實出勤，也不把 HR 成員數稱為當日出勤人數。稽核排程仍由稽核員決定，調派提示不阻擋儲存。

## 2. 使用流程與顯示規則

1. 儀表板駐站區的篩選列增加「檢視日期」，預設台北日期的今天。日期只影響調派資訊，不改變稽核週期、候選狀態或既有篩選條件。
2. 每張駐站卡片增加調派摘要。優先顯示待指派需求，其次顯示調入支援、本站人員調出、其他已登錄排班。同日多種狀況並存時，摘要標示最高優先狀況及其餘項數；點摘要可看全部紀錄。
3. 詳情彈窗按「待指派需求／調入本站／自本站調出／本站其他排班」分組，顯示姓名或需求數、目標站與來源站、日期、時間段、班別。HR 既有成員只放在獨立的「編制名單（供對照）」區塊。
4. 「排定稽核」彈窗依自己的「預計稽核日期」顯示同一套調派摘要。開啟既有分派時立即顯示；新增或變更日期時更新；清空日期時收起。此日期獨立於卡片的「檢視日期」。
5. 提供「重新整理調派資料」操作並顯示資料取得時間。切換到已載入日期只做本機計算；首次切換到未載入年度顯示載入中，待後端回應後再渲染。

| 狀況 | 卡片摘要示例 | 分派彈窗提示 |
| --- | --- | --- |
| 待指派需求 | `⚠ 待指派需求 2 名` | `該日有 2 名待指派需求，請核對人力安排。` |
| 調入本站 | `跨站調入 1 人` | `該日有跨站調入支援，請查看時段。` |
| 自本站調出 | `本站調出 1 人` | `該日有本站人員調出，請查看時段。` |
| 其他已登錄排班 | `其他排班 1 筆` | `該日有已登錄排班，請查看詳情。` |
| 資料完整且零筆 | `無已登錄調派` | `該日無已登錄調派；此資訊不代表已確認出勤。` |
| 未設定、載入中、缺表或讀取失敗 | 分別顯示「未啟用」「載入中」「資料未完整」「資料暫不可用」 | 顯示相同狀態，不顯示「無已登錄調派」 |

待指派需求優先於其他狀況，但詳情不得隱藏同日其他紀錄。待指派數以來源紀錄的 `demandCount` 加總，缺值視為 1；已指派人員依 Email 去重，缺 Email 時以紀錄 ID 去重。摘要中的「調入／調出」是調派方向，不推算當日站點實際人數。

## 3. 資料來源與正規化

`env.js` 增加 `TWCOHORT_SPREADSHEET_ID` 空值設定；正式 ID 優先從 Script Properties 同名 key 讀取，未設定時可退回 `ENV` 值。ID 不回傳前端。Web App 目前以部署者身分執行，部署者須有來源試算表讀取權；使用者不必直接取得該表權限。來源名稱固定為 `調派紀錄_{YYYY}`，只讀 C 欄「資料JSON」，不讀測試表，不修改來源。來源表欄位索引依本專案慣例集中於 `env.js` 的 `COL`。

`DataService.js` 批次讀取年度表，逐列解析 JSON。只保留 `status === '有效'`、紀錄 ID、站碼與日期有效、`startDate <= endDate` 的紀錄；單列 JSON 壞掉或必要欄位無效時略過並記錄筆數。站碼去空白並轉大寫，日期以 `YYYY-MM-DD` 字串比對。舊資料可依來源契約以 `workDate` 補起日，缺迄日時以起日補足。

每筆正規化資料包含 `id`、`stationCode`（目標站）、`originalStationCode`（來源站）、`startDate`、`endDate`、`nurseName`、`nurseEmail`、`startTime`、`endTime`、`shiftName`、`hours`、`note`、`demandCount`、`isPending`、`isTemporary`。`isPending` 由來源的 `assignmentStatus === '待指派'` 或 `nurseName === '待指派'` 推得；`isTemporary` 以來源站與目標站不同為準。前端不取得來源表 ID、建立者或更新者等內部欄位。

每站每日期的比對同時看：

- `stationCode === 本站`：調入本站、待指派需求、或本站其他排班。
- `originalStationCode === 本站 && stationCode !== 本站`：本站人員調出。
- `startDate <= 查詢日期 <= endDate`：跨日紀錄在涵蓋日期都顯示。

待指派紀錄只在**目標站**計入需求；即使有來源站，也不得當成該站已調出的人員。來源與目標相同的紀錄只列一次。時間段顯示順序為「起訖齊全 → 僅起時 → 班別及工時」，不以工時推算實際到勤。

## 4. 跨年度按需載入與 API

twCohort 依紀錄**起始年**存入 `調派紀錄_{YYYY}`，且現有來源程式未限制調派最多只能跨一年。查詢年份 `Y` 的任一日期時，後端列舉試算表內符合正式命名的年度表，讀取起始年不晚於 `Y` 的各表，只保留 `endDate >= Y-01-01 && startDate <= Y-12-31` 的紀錄，並按 `id` 去重。已讀取的來源年度可按年快取，避免重複解析。可選任意有效日期，但只接受 2000–2100 年；若來源年度表太多導致讀取成本不可接受，須量測後再決定分頁或縮小查詢範圍，不可靜默漏掉較早開始的紀錄。

初次 `getAuditDashboard()` 同時回傳今天所屬年份的調派快照。前端以年份儲存已載入快照；切到未載入年份時呼叫新增的唯讀 API `getStationDispatchSnapshot(year, forceRefresh)`，仍使用現有 JSON 字串回應格式。載入期間不沿用上一年的「無調派」結論。同一年並發請求只發一次，較晚完成的舊請求不得覆蓋目前選取日期。重新整理以 `forceRefresh === true` 略過並更新後端快取，重新取得目前年份及取得時間。

年度快照回應格式：

```javascript
{
  year: 2026,
  state: 'ready' | 'partial' | 'unavailable' | 'notConfigured',
  loadedYears: [2024, 2025, 2026], // 本次實際讀到的來源年度
  missingYears: [],
  fetchedAt: '2026-10-07 10:30:00', // Asia/Taipei
  dispatches: [/* 正規化紀錄 */]
}
```

`ready` 表示查詢年的年度表存在，且已列舉的歷史正式年度表均成功讀取、必要資料均有效（空表可為零筆）；查詢年表不存在、已列舉的表讀取失敗、或部分列損毀為 `partial`，已讀到的紀錄仍可顯示，但不得從零筆推斷「無已登錄調派」；外部試算表權限或服務整體讀取失敗為 `unavailable`；ID 未設定為 `notConfigured`。若年度表序列在最早表與查詢年間有缺口，也標為 `partial` 並列於 `missingYears`。未來年度表尚未建立時為 `partial`，明示「年度資料未完整」。

快取以來源 ID、年度及資料版本組成 key，TTL 300 秒。單筆 CacheService 值不得超過 100 KB；年度正規化 JSON 超過上限時跳過快取並照常回傳。快取只是效能措施。頁面資料是 `fetchedAt` 時間點的快照；重新整理前不保證與 twCohort 即時一致。

## 5. 本專案整合與異常

- `code.js` 在完成既有角色檢查後，於 `getAuditDashboard()` 增加 `dispatchSnapshot`，並新增 `getStationDispatchSnapshot(year, forceRefresh)`。新 API 使用相同角色檢查，禁止 `FORBIDDEN` 角色直接呼叫；來源故障不得讓原有儀表板失敗。
- `buildStationDashboardCore_()` 保持稽核週期與駐站評估職責。調派快照在 `getAuditDashboard()` 組裝層加入，避免稽核寫入後的單卡更新重讀外部表。
- `index.html` 在駐站卡片渲染時使用獨立摘要函式；原有稽核狀態徽章、成員展開、歷史紀錄及分派操作維持原本行為。調派摘要使用可聚焦按鈕，避免觸發卡片背景的歷史紀錄彈窗。
- 分派彈窗在開啟及日期變更時查同一份快照。未載入年份先顯示載入狀態，完成後只更新提示，不改動日期輸入值或儲存流程。
- 姓名、Email、備註及站名顯示前均經 `escapeHtml`；備註只在詳情顯示。
- 既有 `outsourcedStations` 也顯示調派摘要；查站與彈窗流程須能找到委外站，不改動其稽核週期規則。

未設定來源 ID 時，日期選取器與調派摘要可隱藏，既有稽核功能照常運作。已設定但缺表、解析部分損毀、無權限或服務失敗時，調派區明示狀態並保留稽核操作；不回傳空陣列假裝資料完整。只記錄錯誤類型與筆數，不在前端或一般日誌輸出完整調派 JSON。重新整理失敗時顯示錯誤及舊快照時間，不把舊快照呈現為最新資料。

## 6. 驗收、測試與部署

新增可在 Node 執行的純邏輯測試，涵蓋站碼與日期正規化、跨日及跨年比對、調入／調出／待指派分類、`demandCount` 加總與去重、同日多狀況優先序、時間段格式及資料狀態判讀。後端試算表讀取以測試替身驗證批次讀取、多年度合併與較早年度開始的長區間紀錄、缺表／解析損毀／權限異常，且既有 `getAuditDashboard()` 仍成功。

本機 `mockServer` 提供調入、調出、待指派、零筆、跨年及失敗資料。手動驗收至少確認：卡片日期切換；首次跨年度載入與回切；調派詳情；分派彈窗既有日期、變更日期及清空日期；重新整理；委外站；來源未設定與讀取失敗。另以實際年度資料量量測首次載入與快取大小，避免新增功能明顯拖慢原有儀表板。

部署者取得 twCohort 資料試算表的唯讀權限，於 Script Properties 設定 `TWCOHORT_SPREADSHEET_ID`，重新部署 Web App。此功能不新增或遷移本專案工作表，也不要求修改 twCohort。部署後以稽核員與禁止存取角色各驗證一次資料可見性。
